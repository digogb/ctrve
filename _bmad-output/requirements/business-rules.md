# Regras de Negócio — CTRVE (Checklist de Transporte de Veículos)

| ID | Descrição | Condição | Ação | Exceção | Estória |
|----|-----------|----------|------|---------|---------|
| RN-001 | Autenticação de usuário | Usuário informa credenciais (usuário + senha) na tela de login | Sistema valida credenciais contra base de dados e, se válidas, cria sessão autenticada (MSG-024) e redireciona à tela principal | Credenciais inválidas: sistema exibe mensagem genérica de erro (MSG-001) sem indicar qual campo está incorreto | US-001 |
| RN-002 | Expiração de sessão por inatividade | Sessão autenticada permanece sem interação por período configurável (padrão: 30 minutos) | Sistema encerra a sessão e redireciona à tela de login com mensagem informativa (MSG-002) | N/A — a expiração é comportamento padrão sem caso excepcional | US-001 |
| RN-003 | Unicidade de matrícula no cadastro | Usuário tenta cadastrar novo usuário com matrícula já existente na base | Sistema impede o cadastro e exibe mensagem de erro (MSG-003). Cadastro bem-sucedido exibe mensagem de sucesso (MSG-023) | N/A — a validação é determinística, sempre rejeita duplicata | US-002 |
| RN-004 | Requisitos de senha | Usuário define senha no cadastro ou alteração | Senha deve ter no mínimo 8 caracteres, incluindo ao menos uma letra maiúscula, uma minúscula e um número | Senha não atende requisitos: sistema exibe mensagem de validação (MSG-004) indicando os critérios não atendidos | US-002 |
| RN-005 | Campos obrigatórios das Informações Gerais | Responsável tenta salvar checklist de entrega | Sistema exige preenchimento de: Placa, Unidade, Motorista, Matrícula, Quilometragem Inicial | Campos obrigatórios vazios: sistema exibe mensagem de validação (MSG-005) identificando cada campo não preenchido | US-003 |
| RN-006 | Formato de placa do veículo | Responsável informa a placa do veículo | Sistema valida formato Mercosul (ABC1D23) ou formato antigo (ABC-1234), aceitando ambos | Formato inválido: sistema exibe mensagem de erro (MSG-006) com os formatos aceitos | US-003 |
| RN-007 | Matrícula numérica | Responsável informa a matrícula do motorista | Sistema aceita apenas valores numéricos no campo matrícula | Valor não numérico: sistema exibe mensagem de validação (MSG-007) | US-003 |
| RN-008 | Bloqueio de entrega duplicada | Responsável tenta criar checklist de entrega para um veículo (placa) que já possui entrega aberta (sem devolução concluída) | Sistema impede a criação e exibe mensagem de erro (MSG-008) | N/A — regra de integridade do fluxo, sem exceção permitida | US-003 |
| RN-009 | Busca por placa | Usuário informa placa (parcial ou completa) no campo de busca | Sistema retorna lista de checklists cuja placa contenha o texto informado, ordenados por data de entrega decrescente | Nenhum resultado encontrado: sistema exibe mensagem informativa (MSG-009) | US-004 |
| RN-010 | Verificação completa dos itens do checklist | Responsável tenta salvar checklist (entrega ou devolução) | Sistema exige que todos os 20 itens de verificação tenham sido respondidos (OK ou Não OK) | Itens pendentes: sistema exibe mensagem de validação (MSG-010) listando os itens não verificados | US-005, US-008 |
| RN-011 | Seleção exclusiva de nível de combustível | Responsável seleciona nível de combustível | Sistema permite selecionar exatamente uma opção entre 1/4, 2/4, 3/4 e 4/4 | Nenhuma opção selecionada ao salvar: sistema exibe mensagem de validação (MSG-011) | US-005, US-008 |
| RN-012 | Registro de data e horário | Responsável preenche checklist de entrega ou devolução | Sistema registra data e horário informados pelo Responsável | Data ou horário não informados: sistema exibe mensagem de validação (MSG-012) | US-005, US-008 |
| RN-013 | Tipo de avaria obrigatório ao marcar ponto | Responsável marca um ponto de avaria no mapa gráfico do veículo | Sistema exige a seleção do tipo de avaria (Risco, Amassado ou Trincado) para cada ponto marcado | Ponto marcado sem tipo: sistema impede o salvamento e exibe mensagem de validação (MSG-013) | US-006 |
| RN-014 | Mapa de avarias exclusivo da entrega | Responsável acessa checklist de devolução | Sistema não exibe a seção de mapa de avarias no checklist de devolução | N/A — comportamento fixo da interface, não há caso excepcional | US-006 |
| RN-015 | Obrigatoriedade de ambas as assinaturas | Responsável tenta salvar checklist (entrega ou devolução) | Sistema exige que ambos os campos de assinatura (Responsável e Motorista) estejam preenchidos | Assinatura ausente: sistema exibe mensagem de validação (MSG-014) indicando qual assinatura está faltando | US-007, US-009 |
| RN-016 | Imutabilidade de assinatura após salvar | Checklist foi salvo com sucesso | Sistema bloqueia edição dos campos de assinatura. Assinaturas são armazenadas como imagem e não podem ser alteradas | N/A — proteção de integridade, sem exceção permitida | US-007, US-009 |
| RN-017 | Devolução exige entrega prévia | Responsável tenta iniciar checklist de devolução para um Nº de Controle | Sistema verifica se existe entrega concluída (salva) para o mesmo Nº de Controle. Somente permite devolução se a entrega existir | Entrega não encontrada: sistema exibe mensagem de erro (MSG-015) | US-008 |
| RN-018 | Herança de dados na devolução | Responsável inicia checklist de devolução | Sistema preenche automaticamente os campos de Informações Gerais (Placa, Unidade, Subunidade, Motorista, Matrícula, Quilometragem Inicial) a partir da entrega correspondente. Campos herdados não são editáveis | N/A — comportamento automático sem intervenção do usuário | US-008 |
| RN-019 | Consistência de quilometragem e data | Responsável informa Quilometragem Final e Data de Devolução | Sistema valida: Quilometragem Final >= Quilometragem Inicial da entrega. Data de Devolução >= Data de Entrega | Valor inconsistente: sistema exibe mensagem de erro (MSG-016 para quilometragem, MSG-017 para data) | US-008 |
| RN-020 | Observações opcionais | Responsável preenche ou deixa vazio o campo de observações | Sistema aceita texto livre sem limite rígido visível. Campo é opcional em ambos os checklists (entrega e devolução) | N/A — campo opcional por definição | US-010 |
| RN-021 | Validação completa antes de salvar | Responsável aciona botão "Salvar" | Sistema executa todas as validações aplicáveis (regras de campos, itens, combustível, avarias e assinaturas) antes de persistir. Se alguma falhar, não persiste e exibe todas as mensagens de erro/validação aplicáveis de uma vez. Salvamento bem-sucedido exibe mensagem de sucesso (MSG-022) | N/A — validação é pré-condição do salvamento | US-011 |
| RN-022 | Confirmação antes de salvar | Todas as validações passaram com sucesso | Sistema exibe mensagem de confirmação (MSG-018) antes de persistir definitivamente. Checklist só é salvo após confirmação positiva do usuário | Usuário cancela confirmação: sistema retorna ao formulário sem salvar | US-011 |
| RN-023 | Geração de PDF | Usuário aciona "Compartilhar" ou "Imprimir" em um checklist salvo | Sistema gera PDF contendo: dados gerais, itens verificados com status, nível de combustível, mapa de avarias (se entrega), assinaturas, observações. PDF disponível para download, compartilhamento e impressão. Geração bem-sucedida exibe mensagem de sucesso (MSG-025) | Checklist não salvo: botões "Compartilhar" e "Imprimir" ficam desabilitados (MSG-019) | US-012 |
| RN-024 | Cancelamento com descarte de dados | Responsável aciona botão "Cancelar" antes de salvar o checklist | Sistema exibe mensagem de confirmação (MSG-020). Se confirmado, descarta todos os dados preenchidos e retorna à tela principal | Usuário nega confirmação: sistema retorna ao formulário mantendo os dados | US-013 |
| RN-025 | Alerta de dados não salvos ao navegar | Usuário aciona "Voltar" ou tenta sair da tela com dados não salvos | Sistema exibe alerta (MSG-021) informando que há dados não salvos. Oferece opções: continuar editando ou sair sem salvar | Sem dados alterados: navegação ocorre sem alerta | US-014 |
